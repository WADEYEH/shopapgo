## 0. 摘要

购物车与结账负责顾客从「加入购物车」到「按下付款」之间的每一步：显示品项和金额、收集联络资料和收件地址、检查每个栏位、验证地址、建立结账纪录，最后交给付款模块。付款成功后，订单核心才用这笔结账建立订单（D36）。

三个原则：

- **金额只由后端算。** 浏览器显示的价格只是给人看，实际收款金额以后端为准。
- **不能出货的订单，在结账时就挡下。** 配送范围、PO Box、地址验证、栏位长度、库存，全部在付款前检查，不会等到送 Amazon 才失败。
- **同一套地址规则，所有付款方式都适用。** 包括地址来自 PayPal 帐户的情况（D16）。

不管页面最后放在 www 或 store（D9 正在跟同事讨论），本规格的规则都一样。

| 项目 | 规则 | 情境 |

## 3. 结账页

### 3.1 流程

1. **联络资料**：Email、电话、营销同意（预设不勾）。
2. **收件地址**：名、姓、地址一、地址二、城市、州、ZIP。州的下拉选单只列 48 州加 DC。
3. **地址验证**：按「继续」时验证地址（见第 4 节），通过才往下走。
4. **确认金额**：显示小计、运费、税、总额。这一步的金额就是最终要收的钱。
5. **选付款方式**：信用卡、Apple Pay、Google Pay、Airwallex Pay、PayPal，一次只能选一种。
6. **付款**：交给付款模块（M5）。付款成功后订单才成立，顾客到订单完成页。

### 3.2 栏位规则

画面上的检查是为了方便顾客；后端会用同一套规则再检查一次，前端的检查不能取代后端。

| 栏位 | 必填 | 规则 | 错误讯息（英文，给顾客看） | 情境 |
|---|---|---|---|---|
| Email | 是 | 格式正确，最长 254 字元 | Enter a valid email address. | C2 |
| Email 拼错 | — | 常见网域拼错时提示，但不阻挡（例如 gmial.com → gmail.com） | Did you mean name@gmail.com? | C3 |
| 电话 | 是 | 美国 10 码电话，可含 +1、括号、空格、横线 | Enter a 10-digit US phone number. | C9 |
| 名、姓 | 是 | 只收英文字母、空格和常见符号；名＋姓合计最多 50 字元（Amazon 的上限） | Enter your first and last name using English letters. | C8 |
| 地址一 | 是 | 最多 60 字元；不能是 PO Box 或军邮 | We can't ship to PO boxes or military addresses. | C5、C8 |
| 地址二 | 否 | 最多 60 字元 | | C8 |
| 城市 | 是 | 最多 50 字元 | | C8 |
| 州 | 是 | 只能是 48 州加 DC | We currently ship only to the 48 contiguous states and DC. | C4 |
| ZIP | 是 | 5 码或 5+4 码，而且要跟州对得上 | This ZIP code doesn't match the state you selected. | C6 |
| 营销同意 | 否 | 预设不勾 | | C10 |

**超过长度不能直接截断。** 现在的程式遇到太长的栏位会直接截掉，不会告诉顾客；改成显示错误，请顾客修改。

### 3.3 结账资料暂存

顾客重新整理结账页时，已填的联络资料和地址会保留（landing 已经做好）。资料存在分页的暂存区（sessionStorage），关掉分页就清除，不会长期留在共用电脑上。

### 3.4 美国以外的访客

可以正常浏览和加入购物车。进结账时就清楚说明只送美国 48 州和 DC，州的选单里也没有其他地区（A8）。

## 4. 地址验证（D18）

团队没有人会看地址，所以每个地址都要在付款前由地址验证服务检查。

| 验证结果 | 处理 |
|---|---|
| 地址正确 | 直接通过 |
| 地址可以投递，但写法和标准不同（例如缩写、ZIP+4） | 显示建议的写法，让顾客选「用建议的」或「用我输入的」，记录顾客的选择 |
| 缺门牌、公寓或楼层号 | 请顾客补上；顾客确认「没有公寓号」后才能继续 |
| 无法投递 | 挡下，请顾客修改 |
| 是 PO Box 或军邮 | 挡下（第 3.2 节） |
| 验证服务暂时连不上 | 先放行（只做第 3.2 节的检查），订单标记「地址未验证」，并通知团队 |

**PayPal 的地址也要过这一关（D16）。** 顾客没在网站填地址、改用 PayPal 帐户里的地址时，付款模块在请款前把地址交给这里检查，不通过就不请款。

**验证结果存在订单上**：验证状态、标准化后的地址、顾客是否接受建议（M4 的栏位）。

**服务**：Google Address Validation（D32），每月前 5,000 次免费。

**实作说明（10/7）**：

- 顾客按「Continue to payment」时检查一次；建立付款时 Worker 再检查一次，跳过页面检查的请求也过不了。同一个地址 15 分钟内不重复问 Google。
- 「建议写法」只在顾客看得出差别时才问：只多了 ZIP+4、大小写不同、公寓号写在第一行或第二行，都直接通过，不打扰顾客。
- 地址未验证（还没设 Google 金钥、Google 没回应、或地址是 PayPal 给的）：照样成立订单，团队收到的新订单通知会加一行「Address not verified」，后台订单页也会显示。
- 检查结果存在订单的地址资料里（`shipping.addressCheck`），不用改资料表。

## 5. 结账纪录与金额（D36）

订单要等付款成功才成立，跟 Shopify 一样。在那之前，顾客的资料和金额存在「结账纪录」里。

- **什么时候建立**：顾客第一次按付款、选 Airwallex Pay，或按 PayPal 按钮时。后端用当下的价格、运费、税重新算一次，锁定金额，并配好编号（`APGO-US-` 开头）；付款成功后，这个编号就是订单编号（M4 第 2.1 节）。
- **金额变了**：算出来的金额跟顾客看到的不同（例如刚好改价），先请顾客确认新金额再付款（C12）。
- **一次购买只有一笔结账纪录**：顾客重复按、重新整理、来回切换付款方式，都沿用同一笔。改了购物车或地址，就更新同一笔并重新报价，原本的付款单作废，付款时再重开（M5 第 3.4 节）。正式环境现在有 39 张待付款订单，就是每按一次就建一张造成的。
- **付款前不算订单**：不寄信、不送出货、不算进订单列表和报表；后台在「未完成结账」页看得到（M9）。
- **24 小时没付款就失效**（情境 D8）：先向付款服务确认没有付款成功、也没有正在处理的付款，再作废所有付款单，标为已失效；不寄信。付款服务还在确认中的（例如 PayPal 的延迟付款）不会失效。
- **失效后才付款成功**：照样成立订单，并通知团队（M4 第 3.4 节）。
- **个人资料保存 30 天**：未完成结账的 email、电话、地址在建立 30 天后删除，只留统计用的数字；隐私权政策同步写明。
- 付款栏位载入失败（例如 Airwallex 暂时故障）时，显示错误和「再试一次」按钮；结账维持进行中，顾客可以改用其他付款方式（C15）。

| 结账状态 | 意思 |
|---|---|
| 进行中 | 已建立，还没付款成功 |
| 付款处理中 | 顾客已完成付款动作，付款服务还在确认 |
| 已完成 | 付款成功，订单已成立 |
| 已失效 | 24 小时没付款，付款单已作废 |

## 6. 税

- 要不要收、在哪些州收，等会计师意见（企划 O1）。
- 程式上保留一个可以替换的计税步骤：目前回传 $0，并在后台标示「未计税」。之后可以改成依州别税率，或接计税服务。
- 如果要收税，税额要在第 3.1 节第 4 步就显示出来，PayPal 订单的金额明细也要包含税。

## 8. 决定纪录

| # | 问题 | 建议 |
|---|---|---|
| 1 | 运费每单 $7.99，确认吗？（企划 O3） | 确认（10/6，D31）。之后要调整只改设定，不用改程式 |
| 2 | 地址验证服务用哪一家？ | Google Address Validation（10/6，D32）。每月前 5,000 次免费，之后每 1,000 次 $17。要在 Google Cloud 建专案并绑信用卡，设好用量上限和费用提醒；隐私权政策要列出 Google。比较过的其他选项：Smarty 没有长期免费方案（每年 $552 起）；USPS 官方 API 预设每小时只能查 60 次，而且今年起要签授权、分级收费 |

## 9. 跟现有代码的差距

| 项目 | 现在 | 要做的 |
|---|---|---|
| 购物车、数量上限、后端报价 | ✓ | 沿用 |
| 运费每单 $7.99、只有标准配送 | ✓ 拿掉加急；结账显示「Most orders arrive in 3–5 business days」（运费政策的说法）（10/7） | — |
| Email、姓名、地址、州、ZIP 的基本检查 | ✓ | 沿用，再加上以下几项 |
| 配送范围 48 州加 DC | ✓ 州的选单只有 48 州加 DC；报价、结账、PayPal 后端都拒绝其他州（10/7） | — |
| PO Box、军邮 | ✓ 地址一、地址二、城市（APO／FPO／DPO）都检查，前后端同一套规则（10/7） | — |
| ZIP 对州 | ✓ 依 USPS 的 ZIP 前三码对照，加上 5 个跨州的 ZIP（10/7） | 少数跨州的 ZIP 不在表上时会被挡；接上 Google 后再看要不要放宽 |
| 电话 | ✓ 必填，只收美国 10 码，存成 +1 开头；跟着地址给 Amazon 出货（10/7） | — |
| Email 拼错提示 | ✓ gmail、yahoo、hotmail、outlook、icloud、aol 的常见拼错，按一下就改，不阻挡（10/7） | — |
| 栏位长度对齐 Amazon | ✓ 名＋姓 50、地址每行 60、城市 50，超过就显示错误，不截断（10/7） | — |
| 地址验证 | ✓ 程式完成（第 4 节的五种结果都有）；还没设 Google 金钥，所以现在每张订单都是「地址未验证」（10/7） | 你建 Google Cloud 金钥并设成 Worker 密钥 `GOOGLE_ADDRESS_VALIDATION_KEY` |
| PayPal 地址检查 | △ PayPal 回传的地址要先过第 3.2 节的规则才请款；我们的结账一定把已检查的地址交给 PayPal，顾客在 PayPal 改不了（10/7） | PayPal 帐户里的地址送 Google 检查，跟 M5 一起做 |
| 一次购买一笔结账纪录，付款成功才成立订单 | ✗ 每按一次就建一张订单 | 新增（D36） |
| 未完成结账 24 小时失效、30 天删除个人资料 | ✗ | 新增 |
| 缺货、停售挡下 | ✗ | 新增（库存由 M6 提供） |
| 结账资料暂存 | ✓（landing，存在 sessionStorage） | 沿用 |
| PayPal 与信用卡二选一 | ✓（landing） | 沿用 |
| 计税步骤 | △ 有设定结构，一律 $0 | 保留可替换的设计，等会计师意见 |
