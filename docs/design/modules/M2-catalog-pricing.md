## 0. 摘要

所有商品资料和金额规则的唯一来源。产品页、购物车、结账、结构化资料、后端收款金额，全部从这里读，避免同一个数字在不同地方写得不一样。

---

## 1. 商品资料

每个商品一份资料：

| 栏位 | 说明 |
|---|---|
| 网址名称 | 例如 `colored-glaze` |
| 网站 SKU | 例如 `d204` |
| Amazon seller SKU、ASIN | 出货用（M6） |
| 名称、容量 | |
| 价格 | D204 $59.99、D215 $29.99（D3） |
| 图片、卖点、FAQ | 文案只用 claim ledger 核准过的说法 |
| 组合包组件 | 组合包才有：`[{ sku, 数量 }]`（A6） |

**停售**：商品资料写在代码里，但「停售」状态存在数据库，后台可以随时切换、立即生效，不用部署（A4）。停售的商品不能加入购物车，购物车里已有的也不能结账。

---

## 2. 金额规则

| 项目 | 规则 | 决定 |
|---|---|---|
| 价格 | 跟 Amazon 一致，但不自动同步；要改价就改商品资料并部署 | D3 |
| 改价对订单的影响 | 已建立的订单金额锁定，不受影响；购物车重新报价时显示新价格 | C12 |
| 运费 | 每张订单 $7.99，只有标准配送；金额是设定值，改金额不用改程式 | D31 |
| 税 | 可替换的计税步骤，目前一律 $0，后台标示「未计税」；等会计师意见（O1） | D5 |
| 折扣码 | 第一版不做；Amazon 的优惠券不同步 | A7 |
| 紧急改价 | 保留现有的设定覆盖功能（`PRICING_JSON`），出状况时不用改程式就能调 | — |

**组合包**：价格另外订；库存取各组件「可售量 ÷ 每包需要量」的最小值（M6）；送 Amazon 时拆成单品（M6）。

**金额只由后端算**：前端显示的价格只是给人看，实际收款金额永远由这个模块在后端算出。
