## 0. 摘要

顾客看得到的页面：首页、22 篇指南、商品总览、两个产品页、订单状态页、政策页、联络我们页，以及搜索引擎需要的资料（sitemap、结构化资料）。

所有顾客页面都在 www.shopapgo.com（D37）。staging 已经是这个样子：品牌页和商店页由同一个 Worker 提供（阶段 2 第一步）。

---

## 1. 负责与不负责

| 负责 | 不负责（由谁负责） |
|---|---|
| 所有顾客看得到的页面的呈现与导航 | 商品资料、价格、运费、税（M2） |
| SEO：sitemap、结构化资料、不收录的页面 | 购物车与结账的流程和检查（M3） |
| 订单状态页的显示 | 订单资料（M4） |
| 联络我们页（表单送出后由 M8 寄到客服信箱） | 政策文字的内容与审核（M11） |

## 2. 页面与规则

| 页面 | 规则 |
|---|---|
| 首页、指南 | 每页都能走到商品。原本 5 个 Amazon 按钮改成「看商品」或「加入购物车」（A1） |
| 页首 | 品牌页和商店页共用同一个页首：「Shop」连到商品总览，加上购物车图示和件数（D39） |
| 商品总览 `/products` | 列出所有上架商品，之后的组合包也放这里（D39） |
| 商品页网址 | `/products/atomic-colored-glaze`（D204）、`/products/atomic-glaze-coating`（D215）。旧网址 `/products/d204`、`/products/d215`（含 `.html`）301 转到新网址（D39） |
| 商品总览、产品页 | 价格、运费、送达时间、退货规则全部取自商品资料和政策，文案里不另外写数字（A2）。缺货或停售时显示状态，不能加入购物车（M2、M6） |
| 订单状态页 | 显示订单状态、品项、金额、追踪号；email 遮蔽显示，不显示完整地址（E3、M4） |
| 政策页 | 隐私权、销售条款、退货与退款、运费政策；每一页的页尾都有连结（M11） |
| 联络我们 | 客服信箱，加上姓名、email、讯息的表单（D28） |
| 购物车、结账、订单状态页 | 不让搜索引擎收录 |

**文案规则**：产品文案只能用 claim ledger 核准过的说法（L4），全站不能出现「TO CONFIRM」或未核准的承诺。送达时间只写「大多 3–5 个工作日」，不写保证日期。

**美国以外的访客**：可以正常浏览，结账前清楚说明只送美国 48 州和 DC（A8）。

## 3. SEO

- **什么时候开放收录**：正式上线前商品页维持不收录，阶段 4 切换上线时才开放（10/7，你确认没收录没关系）。
- **sitemap**：自动包含所有可收录的页面（沿用品牌站现有的 sitemap 检查），不包含购物车、结账、订单页。
- **产品页结构化资料**：Product、Offer（价格、库存状态）、运费资讯、退货政策，数字跟政策页一致。
- **指南**：维持现有的 Article、BreadcrumbList、FAQ 结构化资料。

## 4. 旧网址转址（D39）

- store.shopapgo.com 的每个网址都 301 转到 www 的对应页面；`/v3`（旧的商店首页）转到 www 首页。
- 你之后打算删除 store.shopapgo.com（10/7）。转址保留到删除那天为止；删除前要先完成：

1. Airwallex、PayPal 的付款通知网址改到 www；
2. Airwallex 的 Apple Pay 网域改为登记 www；
3. 广告、社群、email 里的连结都改成 www；
4. 看 store 的流量，连续几周接近零。

删除由你在 Cloudflare 操作（企划阶段 5）。

## 6. 跟现有代码的差距

| 项目 | 现在 | 要做的 |
|---|---|---|
| 首页、22 篇指南、SEO | ✓ 品牌站（www） | 沿用；按钮改成连到商品 |
| 产品页内容 | ✓ staging：商品总览和两个商品页是网站本身的 Next.js 页面（D41），内容读商品资料（`lib/shop/product-data.mjs`，经 `lib/shop/catalog.js`；后端读同一个档案）；首页的商品名称、SKU、容量、使用时机、持久时间也读同一份（使用时机统一用商品页的写法，10/8） | — |
| 产品结构化资料 | △ 商品页有 Product（名称、SKU、品牌、图片）；价格（Offer）只在价格核准后才加上 | 补库存状态、运费、退货资讯 |
| 订单状态页 | △ 结账完成页有基本版 | 补上追踪号、遮蔽规则 |
| 政策页 | △ landing 有草稿，内容跟新决定不一致；品牌站没有政策页 | 依 M11 重写 |
| 联络我们表单 | ✗ | 新增（D28） |
| 页面放哪个网站 | ✓ www（D37）；staging 已是单一网站。品牌站有「单一网站开关」（`NEXT_PUBLIC_APGO_US_SINGLE_SITE`）：只有测试站和切换后的 www 打开，所以上面这些连结不会提早出现在现在的 www | 阶段 4 切换时打开 |
| 页首 Shop 和购物车件数 | ✓ staging：品牌页页首有橘色「Shop」按钮和购物车图示＋件数（手机版是 Shop、购物车、Menu；指南移进 Menu），选单最上面有「Cart · 件数」；商店页页首都加了「Shop」（结账页维持精简，不加）。件数读同一个购物车。商品总览和商品页已改用品牌站的页首、页尾（D41）；购物车、结账、政策页还是商店的页首，阶段 2 的 PR 二、三搬过去后全站一致 | www 在阶段 4 切换时一起上线 |
| 商品总览页 | ✓ staging 的 `/products`：列出 D204、D215，价格取自后端，可以直接加入购物车；后端设定里没有的商品自动不显示。商品页的麵包屑、购物车是空的时候的「Choose Dry or Wet」都改连到这里 | 缺货、停售的显示跟 M2、M6 一起做 |
| 商品页新网址与旧网址转址 | ✓ 新网址已用在所有连结；`/products/d204`、`/products/d215`（含 `.html`）和 `/v3` 都 301 到新网址，旧的单一商品页 `/product` 301 到 `/products`，网址后面的参数（广告标记）会保留 | store.shopapgo.com 整站转 www 在阶段 4 切换时做 |
