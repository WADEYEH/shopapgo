## 0. 摘要

后台是你和同事处理订单、出货、售后的地方，网址是 admin.shopapgo.com。

后台只是「操作画面」：所有规则都在各个模块里（例如能不能取消由订单核心判断），后台不另外写规则。

---

## 1. 登录与权限（D33）

一开始只有一个帐号（拥有者）。之后要加人，由拥有者在后台的「成员」页面加入名单，不用找工程师改设定。

| 项目 | 规则 |
|---|---|
| 验证身份 | Cloudflare Access 负责确认「你是谁」：用 Google 帐号登录；没有 Google 帐号的人，可以用 email 收一次性验证码登录 |
| 决定谁能进来 | 后台自己有一份成员名单。通过身份验证、但不在名单上的人，一律挡在门外 |
| 一开始的名单 | 只有一个拥有者帐号：wadeyeh@apgo.com.tw（10/6 确认） |
| 加人、移除 | 只有拥有者能在「成员」页面新增或移除成员；移除后立即失效 |
| 角色 | 拥有者：所有权限，加上管理成员和设定。成员：所有日常操作，但不能管理成员和设定。第二阶段再加「只能查看」 |
| 防止锁死 | 最后一个拥有者不能被移除。拥有者帐号万一无法登录，由工程师按维运文件的步骤恢复 |
| 操作纪录 | 每个动作都记录登录者的身份，不再一律写「admin」（I2）；成员的新增、移除也要记录，并通知拥有者 |
| 自动化脚本 | 共用的 `ADMIN_TOKEN` 只留给脚本，或直接移除 |
| 过渡期 | landing 目前的共用 email＋密码登录，在切换到新版后停用 |

## 2. 画面

| 画面 | 内容 | 情境 |
|---|---|---|
| 首页总览 | 今天、本月的营收和订单数；今天要处理的事：待处理的售后案件、需人工确认的订单、送单失败、拒付期限、退信、库存低于门槛 | I5、I8 |
| 订单列表 | 只列付款成功的订单（D36）。依状态筛选（需人工确认、已付款、出货中、已出货、已取消），也可以筛选有退款、拒付中（依回应期限排序）、冻结中；用订单编号、email、姓名搜寻 | E9、I13 |
| 订单页 | 资料、付款与失败纪录、退款、出货与追踪、寄过的信、操作纪录、相关的售后案件、内部备注；依订单阶段显示可以做的动作 | I10 |
| 未完成结账 | 还没付款的结账：email、品项、金额、建立时间、付款失败的原因、状态（进行中、付款处理中、已失效）；可以用 email 搜寻。用来回答顾客「我付不了款」；不寄提醒信 | I14、D8 |
| 售后案件 | 案件列表与案件页（M7 第 7 节） | — |
| 顾客名单 | 以 email 区分顾客（没有会员帐号）：姓名、email、电话、订单数、累计消费、最后下单日、是否同意收行销信；可以搜寻和排序 | I7 |
| 顾客页 | 这位顾客的所有订单、售后案件、收件地址、内部备注；汇出或删除个人资料（隐私请求，删除时保留法律要求的订单金额，其余去识别化） | I7、E11 |
| 报表 | 依期间显示：营收（商品、运费、税）、退款、净额、订单数、客单价；各商品销量；各付款方式；运费收入对比 Amazon 预估出货费 | I8 |
| 库存 | 每个商品的 Amazon 可售数量、在途数量、缺货门槛（5 件），以及最后更新时间 | I9 |
| 商品 | 每个商品的停售开关，立即生效 | A4 |
| 汇出 | 每月收款与退款明细 CSV，给会计对帐 | I4、D12 |
| 操作纪录 | 全站所有成员的操作，包含成员变动和设定变更；可以依时间和成员筛选 | I11 |
| 成员（只有拥有者看得到） | 新增、移除成员，设定角色 | I6 |
| 我的设定 | 每个成员自己选要不要收团队通知；系统不允许所有人都关掉 | I12 |
| 设定检查 | Amazon 连线检查（只读）、付款通知最近一次收到的时间 | — |
| 付款查询 | 输入 Airwallex 付款编号或 PayPal 订单编号，直接向付款服务查询状态和失败原因（只读，不显示卡号和付款人资料）。10/6 从 landing 的部署版本移植，目前用网址呼叫，第一版后台再加画面 | D2、D3 |

**所有会改变订单的动作都要填原因**；取消订单、改地址、补寄要再确认一次才执行。

## 4. 业界对照与补充（10/6 确认，D34）

以 Shopify、WooCommerce 的后台为参考，比较标准电商后台会显示的资料。标「第一版」的项目全部要做，已经加进第 2 节的画面、第 3 节的验收测试，以及情境清单 I6–I13：

| 区块 | 标准后台通常显示 | 我们目前的规格 | 建议 |
|---|---|---|---|
| 首页 | 今天和这段期间的营收、订单数，以及待处理事项 | 只有待处理事项 | **第一版**：加上今天、本月的营收与订单数 |
| 订单 | 付款状态、出货状态、金额、顾客；订单页有时间轴、内部备注、标签、风险提示 | 大致都有；缺内部备注、标签、风险提示 | **第一版**：内部备注。**第二阶段**：标签、付款服务的风控结果 |
| 未完成的结账 | 填了资料但没付款的结账名单 | 订单改为付款成功才成立后加入（D36） | **第一版**：只查询，不寄提醒信。要不要寄提醒信，第二阶段再决定 |
| 商品与库存 | 商品列表、价格、库存、上架状态 | 只有停售开关 | **第一版**：库存页，显示 Amazon 可售数量、在途数量、缺货门槛。**第二阶段**：在后台改价格和运费 |
| 顾客 | 顾客名单（姓名、email、电话、订单数、累计消费、最后下单日、营销同意）；顾客页（所有订单、地址、内部备注、往来纪录） | 没有 | **第一版**：顾客名单和顾客页；顾客页同时处理隐私请求（汇出或删除个人资料） |
| 报表 | 营收（总额、退款、净额、运费、税）、订单数、客单价、各商品销量、回购率、流量来源与转换率、库存 | 只有每月 CSV 汇出 | **第一版**：简单的销售报表（营收、退款、净额、订单数、客单价、各商品、各付款方式、运费收入对比 Amazon 出货费）。流量与转换率看 GA4，不重做 |
| 折扣与行销 | 折扣码、活动 | 不做（A7） | 维持不做 |
| 设定 | 商店资料、成员与权限、付款、运费、税、通知、政策 | 成员管理（D33）；其他靠设定档 | **第一版**：成员管理、团队通知的收件人（成员自己选要不要收）。**第二阶段**：在后台改运费、税 |
| 操作纪录 | 所有员工操作的纪录 | 只有每张订单各自的纪录 | **第一版**：全站的操作纪录（含成员变动、设定变更） |
| 退货与售后 | 退货申请与状态 | 售后案件（M7） | 已涵盖 |
| 拒付 | 争议列表与回应期限 | 首页有期限提醒 | **第一版**：订单列表加「拒付中」筛选，依期限排序 |
