## 0. 摘要

出货模块负责把已付款的订单交给 Amazon MCF，从现有的 FBA 库存出货，并把出货进度同步回来。

- **自动送单**（D19）：付款后过了 1 小时冷静期（D23），没有冻结条件的订单就自动送 Amazon。
- **同步**：每 15 分钟向 Amazon 查一次进度，拿到追踪号就把订单改成已出货，并寄出货通知。
- **出问题时**：缺货、Amazon 拒单、包裹延迟、寄丢、被退回，都要通知团队，并交给订单核心或售后处理。

我们的程序不保管 Amazon 的帐号授权，一律透过公司既有的 `amazon-spapi-mcp` 转接程序呼叫 Amazon。

## 2. 送单

### 2.1 送单的条件与时机

订单要同时符合以下条件，才会自动送 Amazon：

1. 状态是「已付款」
2. 付款已满 1 小时（冷静期）
3. 没有冻结条件：不是需人工确认、没有退款登记、没有进行中的拒付（M4 第 3.5 节）
4. 每个商品都对应得到 Amazon 的 seller SKU

排程每 15 分钟跑一次，所以订单大约会在付款后 60–75 分钟内送出。送出后，订单核心把状态改成「出货中」（M4 的 T7）。

### 2.2 送出的内容

| 项目 | 规则 |
|---|---|
| 出货单编号 | 由订单编号产生，固定不变。Amazon 本身不接受重复的编号，这是防止重复出货的最后一道关 |
| 商品 | 网站的商品对应到 Amazon seller SKU（D204 → `D204`、D215 → `D215`）；组合包拆成单品和数量（A6） |
| 配送速度 | 只有标准配送（Standard） |
| 收件地址 | 用送单当下订单上的地址（冷静期内改过的地址也会生效） |
| 包装 | 不特别要求（D8） |
| Amazon 寄给顾客的信 | 关闭。顾客只收我们寄的信，不会另外收到 Amazon 品牌的出货信 |
| 预估出货费 | 送单时记下 Amazon 的预估费用，供每月报表计算每单毛利 |

### 2.3 送单后自动比对（D26）

每次送单成功后，系统马上向 Amazon 读回这张出货单，比对商品、数量、收件地址是否跟我们的订单一致。不一致时通知团队；如果 Amazon 还没开始拣货，同时提供「向 Amazon 取消」的按钮。这项检查取代真实出货测试，不需要有人每单去看。

### 2.4 地址栏位长度

Amazon 出货单的栏位有长度上限，超过会被 Amazon 拒绝。结账时（M3）就要挡下，不能等到送单才失败。依 Amazon SP-API 文件（实作时再核对一次）：

| 栏位 | 上限 |
|---|---|
| 姓名（名＋姓合在一起） | 50 字元 |
| 地址一、地址二 | 各 60 字元 |
| 城市 | 50 字元 |
| ZIP | 20 字元 |
| 电话 | 20 字元 |

## 3. 出货状态

出货模块自己记录比较细的状态，订单核心只看大阶段。

| 出货状态 | 意思 | 订单核心的状态 |
|---|---|---|
| 未送出 | 还在冷静期，或有冻结条件 | 已付款 |
| 送单中 | 正在送 Amazon | 已付款 |
| 已送出 | Amazon 已接单，还没出货 | 出货中 |
| 送单失败 | 连线或资料问题，会重试 | 已付款 |
| 被拒或被取消 | Amazon 回报缺货、地址无效，或已被取消 | 出货中（等售后决定，见第 6 节） |
| 已出货 | 拿到追踪号 | 已出货 |

---

## 4. 同步与追踪

- 每 15 分钟同步一次所有「已送出」的订单。
- 拿到追踪号：回报订单核心（M4 的 T9），并交给通知模块寄出货信；出货信每张订单只寄一次。
- **多个包裹**：Amazon 可能分成好几箱寄出。每个追踪号都要记录，出货信也要全部列出（F6）。
- **延迟提醒**：送出满 2 个工作日还没有追踪号，只提醒团队，不通知顾客（D18 的第 10 条决定）。
- **包裹被退回**：追踪资讯显示退回寄件人时，通知团队，交给售后处理（F9）。
- **已送达**：追踪资讯有送达时间时一起记录；顾客说没收到时，售后要用到（F10）。

---

## 5. 库存

- **库存来源**：Amazon FBA 的可售库存。网站和 Amazon 共用同一批货。
- **更新频率**：每 15 分钟读一次，存起来给前台用，不在顾客每次打开页面时才去问 Amazon。
- **缺货门槛**：可售库存低于 5 件时，产品页显示缺货，也不能结账（A3、B3；10/6 确认，D25）。预留的量是给 Amazon 那边同时卖出用的。
- **组合包**：库存取各组件「可售量 ÷ 每包需要量」的最小值。
- **即使检查过，送单时还是可能缺货**（例如 Amazon 那边刚好卖光），这时按第 6 节的缺货规则处理。

## 6. 出问题时

| 情况 | 处理 | 情境 |
|---|---|---|
| Amazon 暂时连不上、超时 | 自动重试，用同一个出货单编号，不会重复出货；重试多次仍失败就通知团队 | F3 |
| Amazon 授权或资料错误 | 不重试，通知团队处理 | F3 |
| Amazon 回报缺货或无法出货 | 通知团队；寄信告诉顾客会延迟；之后每天重送一次，3 天内补到货就照常出货，否则取消订单并全额退款 | F2 |
| 顾客在冷静期后要求取消 | 向 Amazon 取消。拣货前通常可以取消成功，订单就取消并退款；已经开始拣货就取消失败，改走退货 | E5 |
| 送 Amazon 后才要改地址 | Amazon 不能改已送出的地址，改走取消或送达后处理 | E7 |
| 寄丢或运送中损坏 | 售后决定补寄时，在后台建立补寄单：不向顾客收费，跟原订单连结；另外到 Seller Central 向 Amazon 申请赔偿（不保证成功） | F8 |
| 地址错误被退回仓库 | 通知团队；售后联络顾客决定重寄（顾客填错的收 $7.99）或退款 | F9 |
| 显示已送达但顾客说没收到 | 提供送达时间和追踪资讯给售后；依售后规则补寄一次 | F10 |

## 7. 退货收件

- 退货寄回 Amazon 仓库，走 MCF 的退货流程（G6）。是否同意退货、退多少，由售后（M7）决定。
- 出货模块负责在 Amazon 建立退货授权，并取得退货方式给顾客。Amazon 提供的退货方式会依地址不同，有的需要顾客自己付邮资，细节在售后规格确认。
- Amazon 收到退货后会检查，判定可再售或不可再售，结果记录到订单上，并通知售后（G11）。可再售的会自动回到 FBA 库存。

---

## 8. 后台与通知

**后台**：每张订单显示出货状态、Amazon 的状态、追踪号、错误原因；提供以下按钮：
- 重新送单（送单失败或被拒时）
- 向 Amazon 取消（只在还没出货时出现）
- 建立补寄单（需填写原因）
- 连线检查（只读：确认两个商品在 Amazon 都可以出货）

**通知团队**：送单重试多次仍失败、Amazon 拒单或缺货、送出满 2 个工作日还没出货、包裹被退回、库存低于门槛。

## 9. 正式环境的设定

| 项目 | 现况 | 要做的 |
|---|---|---|
| 连到 `amazon-spapi-mcp`（`AMAZON_OUTBOUND_BASE_URL`、`OUTBOUND_INTERNAL_TOKEN`） | ✗ 正式环境没有 | 新版上线前设定 |
| 商品对应表（`MCF_SKU_MAP_JSON`）、配送速度对应（`MCF_SHIPPING_MAP_JSON`） | ✗ | 同上 |
| 自动送单（`MCF_AUTO_SUBMIT`） | ✗ 关闭 | Hold 测试单通过后开启 |
| Amazon 寄信给顾客（`MCF_NOTIFY_AMAZON_EMAIL`） | 关闭 | 维持关闭 |
| 排程 | ✓ 每 15 分钟 | 沿用 |
| 危险品分类 | 待查 | 在 Seller Central 确认 D204、D215 是否列为危险品；会影响能用的配送方式和地区（F11） |
| 送单验证 | 未做 | 上线前在正式环境建一张 Hold 测试单，Amazon 接受后取消（D26）。需要确认 `amazon-spapi-mcp` 转接程序支援 Hold |
