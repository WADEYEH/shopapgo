## 0. 摘要

所有寄给顾客和团队的信都由这个模块寄出。其他模块只负责说「发生了什么事」，要不要寄、寄什么、寄给谁由这里决定。

寄送方式沿用 shopapgo 已经做好的：先把要寄的信写进数据库，再交给 Resend 寄出，失败会自动重试；Resend 回报的送达、退信、投诉都会记录，退信和投诉的地址会自动停寄。

## 2. 寄给顾客的信

| 信件 | 什么时候寄 | 来源模块 |
|---|---|---|
| 订单确认（兼作收据） | 付款成功 | M4 |
| 出货通知 | 拿到追踪号；多个包裹时列出全部追踪号 | M6 |
| 缺货延迟通知 | Amazon 回报缺货 | M6 |
| 取消确认 | 订单取消 | M7 |
| 改地址确认 | 冷静期内改地址 | M7 |
| 退款完成 | 退款通知回来 | M5 |
| 退货已同意（附退货方式和退货编号） | 售后同意退货 | M7 |
| 退货不符合条件 | 已开封或超过 30 天 | M7 |
| 请补照片 | 瑕疵、损坏申请缺照片 | M7 |
| 补寄已安排 | 建立补寄单 | M7 |
| 请选择补寄或退款 | 寄丢 | M7 |
| 包裹被退回，请重新下单 | 顾客填错地址被退回 | M7 |
| 退款失败，请提供银行帐户 | 退款失败 | M5、M7 |
| 订单逾期取消、款项已退回 | 取消后才付款成功 | M4、M5 |

**确认信的内容**：订单编号、品项、数量、金额明细（小计、运费、税、总额）、付款方式、收件地址、预计送达说法、订单状态页连结、客服信箱。这封信同时当作收据（E10）。

**每张订单的同一种信只寄一次**，即使事件重复送达。

## 3. 寄给团队的信

| 信件 | 什么时候寄 |
|---|---|
| 新订单 | 付款成功 |
| 需人工确认 | 金额不符 |
| 送单失败 | 重试多次仍失败 |
| Amazon 拒单或缺货 | 送单被拒 |
| 出货延迟 | 送出满 2 个工作日还没有追踪号 |
| 包裹被退回 | 追踪显示退回寄件人 |
| 拒付 | 收到争议，内容包含回应期限；期限前 3 天再提醒一次 |
| 退款失败 | 退款失败 |
| 售后案件逾期 | 依 M7 第 3.2 节的期限 |
| 库存低于门槛 | 可售库存低于 5 件 |
| 地址验证服务连不上 | 有订单以「地址未验证」放行 |
| 不合法的状态转换 | M4 拒绝时 |
| 每日异常摘要 | 每天一封，列出以上还没处理的项目；没有就不寄 |

**联络我们表单**：内容直接寄到客服信箱（D28），回信时直接回到顾客的 email。
